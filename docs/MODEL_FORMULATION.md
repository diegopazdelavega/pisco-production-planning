# Model Formulation

This document summarizes the optimization model implemented in `PiscoDet.py`, `PiscoV3_Estc.py`, and the rolling horizon wrappers. It is intentionally close to the current code so it can be used as engineering documentation while the formulation matures.

## Purpose

The model is a mixed-integer linear program for pisco production planning. It coordinates raw alcohol reception, blend preparation, maturation through process-specific routes, storage capacity, labor capacity, and demand fulfillment.

The deterministic model minimizes total cost for one demand trajectory. The stochastic model minimizes expected cost over demand scenarios generated through Sample Average Approximation (SAA).

| Code name | Domain | Meaning |
| --- | --- | --- |

## Objective

The base objective minimizes:

```text
Cost I   = raw alcohol inventory cost
Cost II  = WIP/maturation inventory cost
Cost III = ready stock cost
Cost IV  = backlog penalty
```

In deterministic mode, costs III and IV are direct sums. In stochastic mode, costs III and IV are expected values weighted by `pi[s]`.

Rolling horizon models deactivate the base objective and add a nervousness penalty:

```text
sum(C_nerv * f[a,t])
```

This penalizes changes in the raw alcohol reception plan relative to the previous shifted plan over the non-frozen portion of the horizon.

## Core Constraints

### Ready Stock Balance

For each valid `(n,p)`, the model balances ready stock `k` using:

- previous ready stock, or initial assigned stock `b` at the start of the horizon,
- material maturing out of WIP after `Tau_np[n,p]`,
- outbound flow to the next process if `p` is intermediate,
- demand plus previous backlog minus current backlog if `p` is `refinement`.

The stochastic model indexes `k` and `i_minus` by scenario because demand realization affects ready stock and backlog.

### Raw Alcohol Balance

For each alcohol and day:

```text
v[a,t] = previous inventory + previous-day receipt - recipe consumption
```

At the first active period, the model uses initial inventory `I_a` and scheduled arrivals `W_a`.

### Grouped Initial Inventory Consistency

Initial ready stock may be known only at group level. For each `(group, process)` with initial inventory:

```text
sum(b[n,p] for n in group at process p) = I_Gp[group,p]
```

This lets the optimizer allocate group stock across eligible blends.

### Capacity

The model enforces:

- process storage capacity: WIP plus ready stock cannot exceed `CAP_p[p]`,
- process labor/throughput capacity: daily new WIP entering a process cannot exceed `CAP_labor_p[p]`,
- reception storage capacity: received plus stored raw alcohol cannot exceed reception capacity,
- reception labor capacity: daily alcohol unloading cannot exceed reception labor capacity.

### Lot Sizing

Binary variable `delta[n,p,t]` activates a production/process lot:

```text
Q_min * delta[n,p,t] <= z[n,p,t,0]
z[n,p,t,0] <= M * delta[n,p,t]
```

Raw alcohol reception must be an integer multiple of truck lot size:

```text
q[a,t] = L * l[a,t]
```

### Aging Dynamics

WIP advances one age unit per day until it reaches the process duration:

```text
z[n,p,t,u+1] = z[n,p,t-1,u]
```

On day 1, the same recurrence uses initial aged WIP `gamma[n,p,u]`.

### Process Flow Continuity

The output `x[n,p,p_next,t]` from one process becomes age-zero WIP in the next process:

```text
z[n,p_next,t,0] = x[n,p,p_next,t]
```

Mixing production enters the mixing process directly:

```text
z[n,mixing,t,0] = y[n,t]
```

Recipes connect blend production with alcohol consumption:

```text
w[n,a,t] = y[n,t] * R_ant[n,a,t]
```

## Process Topology

The route graph is implemented in Python by `get_next_process`, not inferred entirely from the workbook:

- `mixing -> refinement` for `n2`,
- `mixing -> barrel` for `n3`,
- `mixing -> infusion` for `n4`, `n5`, and `n8`,
- `mixing -> stabilization` for other blends,
- `barrel -> stabilization`,
- `infusion -> stabilization`,
- `stabilization -> refinement`,
- `refinement` is terminal.

Changing routes in the workbook may not be enough if the above topology changes.

## Stochastic SAA Behavior

`PiscoV3_Estc.py` generates scenarios with:

- normal demand centered at the workbook demand,
- standard deviation equal to `variabilidad * demand`,
- truncation at zero to avoid negative demand,
- equal probability for all scenarios,
- seed `42` for reproducibility.

The default call generates 10 scenarios with 20 percent variability.

## Rolling Horizon Behavior

The rolling horizon wrappers:

1. build the base deterministic or stochastic model,
2. add `RP`, `C_nerv`, `q_bar`, `f`, and nervousness linearization constraints,
3. solve the current horizon,
4. export the current solution,
5. update initial state from period `RP`,
6. shift the previous reception plan into `q_bar`,
7. update demand for the shifted calendar,
8. repeat for the requested number of iterations.

In the stochastic rolling horizon, one realized scenario is sampled according to `pi[s]` and used to update backlog and ready grouped inventory.
